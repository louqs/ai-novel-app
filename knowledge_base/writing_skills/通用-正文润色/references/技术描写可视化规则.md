# 技术描写可视化规则（跨题材通用）

> 来源：吸收自 `AI科幻/写作研究/起点中文网长篇连载科幻小说文笔风格与代入感写作技巧研究报告.md`（§1.1-1.3, §2.2）
> 证据充分性：充分 | 置信度：高

## 核心原则：展示而非告知（Show, Don't Tell）

技术/专业描写的核心问题不是"是否使用术语"，而是"技术是否通过可感知的场景触达读者"。

## 技术可视化三层转化（跨题材通用骨架）

| 转化层 | 目标 | 方法 |
|---|---|---|
| **技术** | 建立信息锚点 | 扼要提及技术名词，作为读者理解的参照点 |
| **场景** | 让技术可感知 | 用角色正在经历的、可被拍成镜头的场景展示技术效果 |
| **情感** | 绑定读者体感 | 通过角色的身体反应、情绪波动来传递技术的冲击力 |

## 各题材通用反例对照

| 题材 | 反面示例（告知） | 正面示例（展示） |
|---|---|---|
| 科幻 | "量子纠缠是粒子间的超距作用" | 主角盯着屏幕——两个节点的状态同步翻转，明明不在同一机房 |
| 医疗 | "患者出现了心源性休克" | 监护仪的波形突然变成锯齿，护士的手刚碰到患者手腕就缩了回来 |
| 法律 | "证据链存在程序瑕疵" | 他把两份打印件并排放好，盯着那个对不上的时间戳，三秒没说话 |

## 通用落地规则

1. **先场景后解释**：先让读者看见发生了什么，再（如需）通过角色对话或内心独白补技术背景
2. **绑定角色视角**：技术描写必须从主视角角色能感知到的东西出发，不跳出全知视角解释
3. **感官优先**：至少命中一种感官（视觉、触觉、听觉）来承载技术信息
4. **术语点到即止**：术语只作为"锚点"，不展开解释；让后续的场景动作完成传达

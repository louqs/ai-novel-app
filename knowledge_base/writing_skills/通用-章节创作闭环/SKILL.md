# 通用-章节创作闭环

## 执行安保（硬性门禁）

### 阅读确认（强制）

**本文件不是摘要或参考提示，而是必须逐字执行的流程指令。**

在产生任何输出之前，必须先逐条输出以下确认。不输出确认就输出正文内容，一律视为流程违规：

```
[阅读确认]
- 本文件 SKILL.md → [已完整读取，完全理解全部硬规则与强制要求]
- references/章节创作闭环总流程与完成出口.md → [已读取并理解]
- references/章节路径推导与工件命名.md → [已读取并理解]
- references/章节批量模式与连续性日志.md → [已读取并理解]
- references/章节终审门槛与摘要规范.md → [已读取并理解]
```

若 Agents.md 声明了主输出平台或注册了三类模板，再追加：

```
- Agents.md → [已读取，已识别主输出平台 / 注册模板]
```

### 执行器定位（硬性）

- **本 Skill 是"执行器"，不是"规划器"**：目标是把步骤 0→12 真实跑完，而不是输出计划、进度条、阶段总结、初稿清单或"接下来将进行什么"的说明。
- **一气呵成**：一旦开始执行，必须一气跑完步骤 0→12，中途不得暂停去询问与任务无关或可由既有规则推断的问题。
- **禁止"等你说继续"式暂停**：不得在中途以"汇报当前进度/下一步计划"为理由停下来等待用户回复。除非硬性缺参导致无法继续，否则必须自动持续执行到步骤 12 的最终摘要输出。
- **步进式输出**：每一步开始时输出 [进度] 步骤 N：当前动作描述；在完成全部步骤之前，不得提前输出"本章节闭环完成"、评分结论或读者产物。

### 阶段推进闸门（硬性）

- 步骤 1 / 2 只代表"正文初稿阶段完成"，绝不代表整个 SOP 完成。
- 每完成一个步骤，必须立即判定 nextStep 并继续推进；只要 nextStep <= 11，就不得输出完成收尾语。
- 批量模式下，整批步骤 0→1.5→2 完成后必须立刻进入步骤 3→5；步骤 3→5 完成后必须进入步骤 6→9.5；全部章节通过 9.5 后才允许进入步骤 10→12。
- 如果发现自己刚完成的是"本相位最后一章"而不是"全 SOP 最后一步"，必须自动切到下一相位，而不是结束对话。

### 禁止误判完成的情形（硬性）

以下任一情况都不等于流程完成，必须继续执行：

1. **禁止把"初稿已写入"当作"章节已完成"** — 只完成步骤 1→2 时最多只能记为 drafted。
2. **禁止跳过步骤 2 后的字数门禁** — 正文修改后都必须重跑 count-chapter.ps1，以最新 MeetsMinCJK/WithinRange 字段为准。**正文字数检测必须使用 `scripts/count-chapter.ps1`**，不得用 `Len`、`NoWhitespaceLen`、编辑器字符数或目测代替；正文门禁只看 `BodyCJK / MeetsMinCJK / WithinRange`，`MeetsMinCJK` 必须为 `True`，`WithinRange` 最好为 `True`。
3. **禁止跳过润色与去AI味（步骤 3→4）直接进审阅** — 初稿必须经过润色和去AI味处理才能进入审阅。
4. **步骤 6→7→8→9→9.5 的首轮闭环必须无条件执行** — 不得根据任何"综合评分"决定跳过、合并或提前终止。
5. **禁止用"文件已存在"代替"步骤已执行"** — 必须以本次执行中是否实际读取、修改、覆盖写回并更新日志为准。
6. **禁止把"旧评分"或"旧报告"当作当前终审结论** — 只要正文在本次执行中发生了任何实质修改，审阅报告就必须重新审阅并覆盖更新。
7. **禁止把"接近 9.2"表述成"已达 9.2+"** — 8.8/8.9/9.0/9.1/9.2 一律视为未达标；只有明确写出综合评分 > 9.2 才达标。
8. **禁止把"阶段性汇报"伪装成"完成汇报"** — 步骤 12 之前只能输出进度，不得出现任何暗示"整个 SOP 已收尾"的表述。

## 风格/蓝本/写作研究模板自动发现规则

若当前服务的项目根目录存在 Agents.md，启动章节创作闭环前必须：

1. 读取项目根目录的 Agents.md；若其中声明了主输出平台，检索三类模板时优先匹配"适用平台"与主输出平台一致的模板，无匹配时回退到"适用平台：默认"的同类模板
2. 若 Agents.md 中注册了"写作研究模板"——读取对应路径的模板文件，将其作为本轮章节闭环的题材×平台默认门禁
3. 若 Agents.md 中注册了"作者风格模板"——读取对应路径的模板文件，将其作为正文创作、润色、去AI味和审阅阶段的统一文风基线
4. 若 Agents.md 中注册了"作品蓝本模板"——读取对应路径的模板文件，将其作为章首、回报、钩子、节奏和信息释放的闭环参照
5. 本 Skill 作为编排器主要负责读取、记录、传递三模板约束，并在日志中标注模板状态；具体字段由被调用的子 Skill 消费
6. 若项目根目录不存在 Agents.md，或其中未注册对应模板——回退通用默认模式，不报错，不阻断

## 主输出平台自动发现规则

若当前服务的项目根目录存在 Agents.md 且其中声明了主输出平台，启动章节创作闭环前必须：

1. 读取项目根目录的 Agents.md
2. 按命名约定定位对应的通用-输出{平台名}版 Skill
3. 将平台 Skill 的门禁标准（字数门槛、开篇密度、回报间隔、钩子强度、标题规则）作为本章节闭环的默认门禁基线
4. 在日志中记录当前主输出平台及对应平台 Skill
5. 若未配置主平台或配置缺失——回退平台无关的通用默认模式，不报错，不阻断

本 Skill 默认消费字段：

- 写作研究模板：章节门禁、章首约束、节奏间隔、禁忌类约束
- 作者风格模板：句长基线、段落节奏、对话风格配置、情绪表达方式、禁忌清单
- 作品蓝本模板：章首模式指纹、中段回报指纹、章末钩子指纹、场景节奏分布、信息释放节拍

## 默认模型温度参考

本 Skill 作为编排器不直接调用模型，但将以下温度约束传递给被调用的下游子 Skill 执行：

| 步骤 / 子 Skill | 推荐温度 | 说明 |
|---|---|---|
| 通用-审阅章节正文（审阅/复审） | 0.3 | 低创造性，保持判断稳定一致 |
| 通用-正文润色 | 0.45 | 方向已定，适度约束 |
| 通用-去AI味重写 | 0.45 | 同上 |
| 通用-创建小说正文 | 0.58–0.70 | 需要创造性与变化 |
| 通用-强化章节开头 / 章末钩子 | 0.45 | 局部强化，适度约束 |
| 通用-生成章节控制卡 | 0.45 | 结构规划，适度约束 |
| 通用-撰写书评 | 0.55 | 需要创造性但不宜跑偏 |
| 通用-润色作者有话说 | 0.50 | 轻创作，保持读者向口吻 |

## 题材包装层路由规则

题材目录下的包装层 Skill（如都市悬疑-生成章节控制卡）是本 Skill 的题材特化扩展。调用规则：

- 在调用任一通用 Skill 之前，先检查当前项目题材目录下的 .github/skills/ 中是否存在同名的题材包装层
- 若存在：**先加载题材包装层 Skill**，再由其路由到通用 Skill 叠加题材规则
- 若不存在：直接调用通用 Skill，不报错，不阻断
- 示例：写都市悬疑章节时 → 先检查都市悬疑-章节创作闭环 → 若存在，用它包装本流程

## 章节创作闭环流程

### 步骤 0：初始化与环境检查

**调用 skill：无（编排器自执行）**

**扮演角色：** 编排器 / 项目经理角色，不代入具体创作/审阅/读者视角，只做环境检查与路径推导。

**职责：** 确认所有输入路径与依赖文件存在，自动发现模板/平台，推导全部工件路径，创建目录结构，初始化 SOP 执行日志。

| 子步骤 | 动作 | 产出 |
|---|---|---|
| 0.0 | 读取项目根目录 Agents.md（若存在），识别主输出平台与注册的三类模板 | 确定平台门禁、模板约束基线 |
| 0.1 | 读取 OUTLINE_FILE（卷纲/章纲），确认本章定位 | 本章定位确认 |
| 0.2 | **裁判源复核**：认真仔细阅读本章实际出场人物对应的人物传记 + 与本章背景/技术/规则/证据/程序链/世界观有关的故事设定文档 | 日志记录本轮核对了哪些裁判源、哪些约束已兑现、哪些待补丁 |
| 0.3 | 若已存在 CONTINUITY_LEDGER_FILE（连续性台账），读取上一章的结构化条目 | 承接上一章余波与钩子 |
| 0.4 | 验证 CHAPTER_FILE 路径，若所在目录不存在则创建 | 目录就绪 |
| 0.5 | 根据 CHAPTER_FILE 推导全部工件路径（见 references/章节路径推导与工件命名.md）：CONTROL_CARD_FILE、REVIEW_REPORT_FILE、READER_NOTE_FILE、BOOK_REVIEW_FILE、CONTINUITY_LEDGER_FILE | 工件路径表 |
| 0.6 | **路径合规校验**：逐项校验派生路径的根目录归属 | 校验通过方可继续 |
| 0.7 | 创建所需目录：写作控制卡/、审阅意见/、阅读笔记/、书评/、SOP执行日志/撰写章节/连续章台账/ | 目录就绪 |
| 0.8 | 初始化 SOP 执行日志（见 references/章节批量模式与连续性日志.md） | 日志写入 |

**完成标记：** checkpoint.nextStep = 1，写入日志。

---

### 步骤 1：生成章节控制卡

**调用 skill：** `通用-生成章节控制卡`（及对应的题材包装层）

**扮演角色：** 规划者 / 写前施工员角色。从大纲控制卡视角拆解本章任务，不代入作者写作情绪，以结构规划为主。

**职责：** 将卷纲/章纲压缩成可执行的本章施工命令，明确本章唯一职责、场景拆分、中段回报预埋、章末钩子预埋与上游供血对齐。

1. 加载通用-生成章节控制卡（若存在题材包装层，先加载题材层再路由到通用层）
2. 控制卡必须回答：本章核心任务、场景单元拆分、中段回报类型与触发条件、章末钩子类型与下一章接棒对象
3. 控制卡必须标注：本章对主卖点的关系（强化/兑现/转化/保温/铺垫）
4. 控制卡落盘到 CONTROL_CARD_FILE（路径必须以写作控制卡/开头）

**文件写入：** 控制卡 → 覆盖写入 CONTROL_CARD_FILE

**完成标记：** checkpoint.nextStep = 2，写入日志。

### 步骤 1.5：写前连续性检查

**调用 skill：** `通用-管理连续性冷热线`（及对应的题材包装层）

**扮演角色：** 规划者视角。在写完控制卡后、正式创作前，检查哪些旧线该在这章回归、哪些线快冷了、本章承接的上一章钩子是否清楚。

**职责：** 检查连续性冷热线状态，确认本章需要回应的旧线、伏笔与关系状态。

1. 加载通用-管理连续性冷热线（及对应的题材包装层）
2. 读取 CONTINUITY_LEDGER_FILE（若存在），检查人物动态状态、悬念/伏笔状态、回归压力与未回收钩子
3. 输出连续性诊断结论：热线/温线/冷线/归档线分类，以及本章必须触碰的对象
4. 若诊断发现关键冷线已连续多章失温，优先在控制卡中追加回归安排

**完成标记：** 诊断结果写入日志。

---


### 步骤 2：撰写章节初稿 → 字数检测 → 循环扩写

**调用 skill：** `通用-创建小说正文`（及对应的题材包装层）；脚本 `scripts/count-chapter.ps1`

**扮演角色：** 小说作者角色。参考 `.github/agents/小说作者.agent.md` 的创作视角，代入项目对应题材的作者立场。创作阶段全情投入写作，字数检测阶段短暂切出执行脚本。

**职责：** 依据控制卡与章纲，创作章节正文初稿并确保达到字数门槛。

| 阶段 | 动作 |
|---|---|
| 2.1 | 加载通用-创建小说正文（及题材包装层），代入作者角色 |
| 2.2 | 依据控制卡 + 大纲 + 人物传记 + 故事设定，创作完整章节正文（含章引语、正文、章末钩子、## 作者有话说、## 章节后记） |
| 2.3 | 完整正文**覆盖写入** CHAPTER_FILE |
| 2.4 | 运行 scripts/count-chapter.ps1 -FilePath "CHAPTER_FILE"，读取 JSON 输出中的 BodyCJK/MeetsMinCJK/WithinRange（**正文字数检测必须使用 count-chapter.ps1**，不得用 Len、NoWhitespaceLen、编辑器字符数或目测代替；正文门禁只看 BodyCJK/MeetsMinCJK/WithinRange，MeetsMinCJK 必须为 True，WithinRange 最好为 True） |
| 2.5 | **判断**：若 MeetsMinCJK == true → 进入步骤 3；若 MeetsMinCJK == false → 调用通用-创建小说正文（扩写模式），循环直至达标 |
| 2.6 | **节拍门禁**：落稿后执行四拍复核（前200字钩子、中段回报、后200字钩子、连续内倾段检查），见 references/步骤2正文四拍与钩子轮换门禁.md |
| 2.7 | **初稿后补检包**：①基础复检4项（重跑 count-chapter.ps1 字数门禁——**正文字数检测必须使用 `scripts/count-chapter.ps1`**，不得用 `Len`、`NoWhitespaceLen`、编辑器字符数或目测代替，正文门禁只看 `BodyCJK / MeetsMinCJK / WithinRange`，`MeetsMinCJK` 必须为 `True`，`WithinRange` 最好为 `True`；若含 `## 作者有话说` 则重跑 `count-afterword.ps1`；扫读是否混入"初稿+二稿"拼接式内容；同步刷新审阅链）；②章节自指检查（清除"这几章/前几章/上一章/本章/后文会"等连载导览腔）；③## 章节后记同步（刷新定位/爽点/伏笔回收/人物发展等字段） |

**文件写入：** 每轮扩写后覆盖写入 CHAPTER_FILE

**完成标记：** checkpoint.nextStep = 3，字数统计与四拍字段写入日志。

---

### 步骤 3：正文润色（组合调用）

**调用 skill：** `通用-正文润色`（及对应的题材包装层）；按需调用 `通用-强化章节开头`、`通用-强化章末钩子`、`通用-执行场景单元`、`通用-执行对话冲突`、`通用-执行微空间受限场景`

**扮演角色：** 小说作者角色（润色视角）。继续沿用 `.github/agents/小说作者.agent.md` 的作者立场，但切换为"精修者"模式——不是重写，而是打磨已有文本。诊断发虚维度时短暂切出为编辑视角，决定是否调用专项 Skill。

**职责：** 对已达字数门槛的章节进行整体文风、节奏、语言质感上的精修，并对局部短板做专项强化。

| 阶段 | 动作 |
|---|---|
| 3.1 | 加载通用-正文润色（及题材包装层），代入作者角色 |
| 3.2 | 读取当前 CHAPTER_FILE 全文，执行整章润色：语言流畅度优化、节奏与张力调整、人物描写与情感描写的细致打磨、证据链/动机链/时间线自洽 |
| 3.3 | 润色结果**覆盖写入** CHAPTER_FILE |
| 3.4 | **专项强化**：逐项诊断并决定是否调用专项 Skill |

**专项强化诊断与调用**（按需执行，不强制全部调用）：

| 诊断问题 | 调用 Skill | 处理范围 |
|---|---|---|
| 章首前 150–300 字抓力不足、首屏留存弱 | 通用-强化章节开头（及题材包装层） | 前 2–3 段，仅局部强化 |
| 章末后 150–300 字翻页感不足、下一章驱动弱 | 通用-强化章末钩子（及题材包装层） | 最后 200 字，仅局部强化 |

## 批量模式

批量模式下，以上步骤按分相位流水线执行，而不逐章串行跑完整链：

| 相位 | 包含步骤 | 说明 |
|---|---|---|

## SOP 执行日志

每次执行本 Skill，都必须在 SOP执行日志/撰写章节/ 中创建或更新一份日志文件，用于断点恢复。

详细日志结构与更新时机见 references/章节批量模式与连续性日志.md。

## 完成定义

### 单章完成

只有同时满足以下全部条件，才允许宣告完成：

1. 步骤 0–11 已在本次执行中实际跑完，而不是依赖历史文件推断。
2. CHAPTER_FILE 已完成创作/补字/润色/去AI味/多轮回炉修订。
3. CONTROL_CARD_FILE 已落盘在写作控制卡/ 目录下。
4. REVIEW_REPORT_FILE 已被本次最新终审覆盖更新，且包含综合评分：X.X/10。
5. 连续两轮独立终审综合评分均严格大于 9.2。
6. 最新字数脚本结果已在正文最新版本上重新核对。
7. READER_NOTE_FILE 与 BOOK_REVIEW_FILE 已在本次执行中生成或覆盖更新。
8. 日志中的 status 与 checkpoint 已与真实状态一致。
9. 当前聊天输出的是步骤 12 的摘要模板，而不是阶段汇报。

### 批量完成

见 references/章节终审门槛与摘要规范.md 中的聚合门禁定义。

## 常见触发词 / 用户说法速查

- 按 SOP 把这章跑完
- 从大纲一路做到终稿
- 这几章都按闭环来做
- 一直回炉到 9.2+
- 批量跑这几章
- 带日志续跑下去别停

## 不适用情形

- 只写一章正文，不跑后续审阅与读者产物：优先使用通用-创建小说正文
- 只做审阅报告，不改稿：优先使用通用-审阅章节正文
- 只做某一步专项强化：优先使用对应专项 Skill

# 规则分类抽样框（R/P/G/S 四象限）

> 用途：诊断写作技能库中"硬规则过载"问题。把每条被写成"必须/禁止"的语句重新归类，
> 区分**真红线**、**工序门禁**、**体裁靶值**、**诊断信号**，从根上化解"规则越多越自相矛盾"。
>
> 适用对象：`通用-正文润色`(32参考)、`通用-去AI味重写`(20+参考)、`通用-审阅章节正文`(14参考)
> 等任何"参考文件多、硬规则密"的技能。

---

## 核心问题

当规则多到一定程度，LLM 不会"选最适合当前文本的规则"，而会**向最容易打勾的可量化规则塌缩**——
能数的（`对话比例25-55%`）压过需要判断的（`选最贴合本段的视角`），文笔因此受损。

**但解法不是再叠一层决策树/优先级表。** 元规则本身也是规则，会让 LLM 去"求解那张表"而非读文本，
把规则官僚主义又加深一层。

**真正的病根是措辞错配**：绝大多数被写成"必须/禁止"的语句，本质是**诊断信号**或**工序纪律**，
不是硬约束。"三秒开头测试"和"环境-人物交互"根本不矛盾——它们是两个互相权衡的信号，
被"必须"框成了**伪矛盾**。先改标签，矛盾自己消失大半，剩下真需要裁决的没几个。

---

## 四象限判据

| 标签 | 一句话测试 | 该有的措辞 | 归宿 |
|---|---|---|---|
| **R 红线** | 违反它，文本就是**错的**（事实/逻辑/连载纪律），且**全体裁成立** | 必须 / 禁止 | 留在通用规则，保留强制语气，控制在极少数 |
| **P 工序门禁** | 约束的是**动作流程**（先读什么、跑什么脚本、回退给谁），与文笔好坏无关 | 必须（但**单列**成"执行纪律"区） | 抽到独立"执行纪律"块，不混进美学规则池 |
| **G 体裁靶值** | 含**可量化阈值**，且换个体裁该值就该变 | 向本体裁靶值靠拢 | 移出规则文件，注入 `genre_skills/` 作为参数 |
| **S 诊断信号** | 违反它文本只是**更弱**，不是错；是"体检项" | 检查 / 倾向 / 优先 | 降级措辞，留作审阅清单 |

### 判据顺序（决策树）

```
对每条"必须/禁止"语句：
  1. 违反 = 错 还是 = 弱？
       错 → 进 R/P/G 继续判
       弱 → S（诊断信号），措辞降级为"检查/倾向"
  2. 管的是流程还是文笔？
       流程（读什么、跑什么、退给谁） → P（工序门禁），抽到独立区
       文笔 → 进 R/G 继续判
  3. 含可量化阈值，且随体裁该变吗？
       是 → G（体裁靶值），移入 genre_skills 参数
       否 → R（真红线），保留强制语气
```

**为什么是这个顺序**：先用"错/弱"切掉最大的 S 噪声；再用"流程/文笔"剥出 P
（它本该强制，只是放错区，是"规则显得多到自相矛盾"的一大成因）；最后用"阈值+体裁敏感"
捞出 G（跨体裁冲突的真凶）。剩下的才是 R。

## 三层落地结构（替代决策树）

体裁差异由第 2 层天然吸收，**无需 N×M 适用矩阵**：

1. **红线（R，~5条以内，全体裁通用）**：违反即错。如"事实账本一致性""伏笔不能凭空消失"
   "不得删关键证据/编号/时间点"。只有这些配"禁止"。
2. **体裁靶值（G，由体裁包注入，不进通用规则文件）**：对话比例、视角分配、零画面阈值等。
   悬疑70%、武侠20%，靠 `genre_skills/` 给定 target，通用规则只说"向本体裁靶值靠拢"。
3. **诊断信号（S，其余全部）**：措辞从"必须/禁止"降级为"检查/倾向"。它们是审阅体检项，
   不是创作枷锁。
4. **工序门禁（P，独立"执行纪律"区）**：流程纪律，强制但与美学无关，单列以免污染美学规则池。

## 抽样方法（可复用脚本思路）

对任一技能目录：

```bash
# 1) 强制语气标记词总频次（识别水分）
for w in 必须 禁止 严禁 不得 不可 一律 绝对 红线 切忌; do
  grep -rho "$w" . | wc -l
done

# 2) 每文件强制密度 = 强制标记数 / 行数（找规则密集文件 vs 例库文件）
for f in references/*.md SKILL.md; do
  m=$(grep -Eo "必须|禁止|不得|不可|红线" "$f" | wc -l)
  lines=$(wc -l < "$f")
  echo "$m $lines $(basename "$f")"
done | sort -rn

# 3) 量化阈值扫描（定位 G 候选——跨体裁冲突真凶）
grep -rnoE "[0-9]+[%％]|[0-9]+ ?字|连续[0-9]+句|[0-9]+秒" . | grep -v 好词好句
```

**两个去噪要点**：
- "好词好句/范文"类例库文件里的"必须/不得"多是**范文正文里的字**，非规则，须排除。
- `不能`高频但多为描述句（"读者不能记住"），不计入强制规则。

## 实跑样本：通用-正文润色 SKILL.md（20条强制句）

| 行 | 句子要点 | 标签 |
|---|---|---|
| 82-85, 388 | 改人物动机/关系前必须读人物传记与设定、核对裁判源 | **P** |
| 144, 394, 395 | 字数必须跑 `count-chapter.ps1`、引用脚本字段、不得目测 | **P** |
| 89, 99 | 存在 `Agents.md` 须按平台门禁加载对应 Skill | **P** |
| 215, 216, 218 | 涉及增删场景/改因果必须退回 writer，不用润色硬扛 | **R**（边界红线）|
| 392 | 不得删关键证据/编号/时间点/规则边界 | **R** |
| 391 | 不得保留章节自指/连载导览腔（"上一章/后文会"） | **R**（连载纪律）|
| 389, 390, 393 | 不得润成说明书/空抒情、不得磨平回报与钩子、不必要不推倒重写 | **S** |
| 151, 219, 344, 367 | 中段须有实质回报、须复核情感弧、须分辨真假节奏 | **S** |
| 133, 150 | 解释>150字必须拆分；概括式开头须改切片式 | **G**（含阈值/体裁敏感）|

**统计结果**：R≈5、P≈7、G≈2、S≈6。

**关键结论**：这 20 条"必须"里，**真红线只占 1/4**；最大块是**工序门禁（35%）**——
伪装成美学规则的流程纪律；而真正引发跨体裁矛盾的**只有 2 条阈值**。
"规则太多自相矛盾"的观感，很大程度来自 P 和 S 被错穿了 R 的外衣。

## 全库强制语气水分参考（通用-正文润色，33文件）

强制语气词合计 372 次，但分布极不均：
- SKILL.md：46标记/395行（真规则密集）
- 9个"好词好句"文件（上万行）：标记多但几乎全是范文正文用字（噪声）

→ **频次高 ≠ 规则多**。先按"强制密度 + 排除例库"定位真正的规则文件，再逐条判据。

# 最佳实践 V2：从灵感到多平台分发（题材 Prompt 入口 + 门禁驱动版）

> 适用范围：本仓库所有题材目录（如 `女频爱情/`、`都市悬疑/`、`异能志怪/` 等）
>
> 核心原则：**用户直接调用的是题材目录下 `.github/prompts/*.prompt.md`，不是通用 Skill。**

---

## 1. 先统一调用架构（避免入口错位）

统一按这条链路工作：

`用户任务 -> 题材目录 Prompt -> 题材 Skill 路由 -> 通用 Skill 能力本体`

意味着：

- 用户在对话里应使用题材 Prompt 能力名（如“竞对分析”“设计大纲”“多平台输出SOP”）。
- 不要让用户直接说“调用通用-xxx skill”。
- `通用skills/` 是能力底盘，不是用户侧入口。

一句话记忆：**对用户说 Prompt，对系统走 Skill。**

### 1.1 长篇与短篇的关键差异（避免方法误用）

长篇与短篇集都能用“门禁 + 回炉”工作流，但落点不同：

- **长篇核心**：跨卷纵深推进（主线、人物弧线、终局压力持续递增）。
- **短篇核心**：单篇独立回报 + 全集辨识度（篇间编排与风格统一）。

实操上，长篇更强调：

1. 卷级推进与卷间承接（不是“很多章节”的简单叠加）
2. 冷热线与回收节奏（避免角色/线索失温）
3. 终局约束前置（避免后期崩盘式补丁）

## 2. 先回答一个关键争议：总纲没成型，先做人设/设定/台账是否合适？

**结论：可以做，但只做“轻量版”，不做“重定稿版”。**

### 2.1 为什么不能过早重投入

- 大纲未稳时，主线目标、卷级推进、终局约束都可能变化。
- 若先重写人物/设定/台账，后续会出现高返工、口径冲突、线索失配。

### 2.2 最优做法：两段式建模

1. **总纲前（轻量底盘）**：只保留最小可行信息
   - 人物：核心欲望 + 关键短板 + 主要关系冲突
   - 设定：3~5 条硬规则（边界/代价/失效）
   - 台账：只登记“主线必须兑现”的关键伏笔
2. **总纲后（重度定稿）**：再扩写完整人物传记、故事设定、线索伏笔台账

## 3. 全流程最优形态：7 段 6 门禁（不是一条直线）

相比"线性九步法"，V2 推荐"分段 + 门禁 + 回环"流程：

0. 宏观市场分析层：宏观市场分析（为项目初始化提供市场证据）
1. 项目初始化段：基于宏观市场分析做平台校准、商业锚定、情绪定位、元设定骨架、套路模组适配
2. 竞对与作品蒸馏段（可选，初始化后验证与细化）：竞对分析找对手、蒸馏研究析对手
3. 探索段：灵感、题材定位
4. 架构段：总纲与分卷骨架
5. 建模段：人物/设定/台账定稿
6. 生产段：正文创作、审阅回炉
7. 发行段：签约评估、组包、多平台分发与数据回流

### 宏观市场分析层（项目初始化前置，必选）

在项目初始化之前，必须先完成宏观层面的市场分析。本层产出将直接作为初始化的决策输入。

调用 `通用-深度研究` 对目标平台×题材进行宏观层面的趋势调研、生态分析与读者画像研究，回答"这个方向上市场正在发生什么"。

- **研究域**：题材趋势研究 + 平台生态研究 + 读者/市场研究
- **输出**：研究报告落盘到 `写作研究/` 目录
- **建议必选**：写新书时强烈建议执行。若已有可靠研究基础可跳过。

已有的宏观研究报告可在新项目中复用，无需每次重新研究。

### 项目初始化段（动笔前必选，接收宏观市场分析）

在完成宏观市场分析之后、设计大纲之前，先调用 `通用-小说项目初始化` 完成项目级战略策划。**初始化过程以宏观市场分析的产出为核心决策依据**：

| 初始化模块 | 核心决策依据 | 情报源 |
| --- | --- | --- |
| 模块1「平台适配校准」中的竞争定位 | 平台生态研究与题材趋势数据 | 宏观市场分析（写作研究/） |
| 模块3「读者情绪定位」 | 读者画像与行为特征 | 宏观市场分析（写作研究/） |
| 模块4「套路模组适配」 | 题材裁判源与平台约束 | 宏观市场分析 + 题材裁判源 |
| 模块7「可行性校验」的差异化验证 | 市场定位综合判断 | 宏观市场分析 |

若初始化过程中发现竞对数据缺失，`通用-小说项目初始化` 会自动调用 `通用-分析竞对作品` 补充竞对差距清单（此时竞对分析以补充角色出现，后续仍可单独深入）。

通过题材包装层（如 `都市悬疑-小说项目初始化`、`女频爱情-小说项目初始化`）路由到通用本体，产出"项目初始化蓝皮书"。

> 入口命令示例：`/小说项目初始化 --platform 起点 --genre 都市悬疑`（或直接使用 `/init` 快捷命令）

### 竞对与作品蒸馏段（初始化后可选，验证与细化）

项目初始化完成后，方向已定、方案已定。此时可调用竞对分析与蒸馏研究，作为定位的验证与细化：

#### 竞对分析（找对手）

调用 `通用-分析竞对作品`，在目标平台上锁定同题材 Top10 候选池，按四层框架深拆 3-5 本核心强样本，输出可横向对比的竞对分析报告。

- **重点关注**：竞品用了什么套路组合、读者在书评区/本章说中的真实反馈、市场饱和度和差异化空间。
- **输出**：每本竞对单独成报告，落盘到 `竞对分析/` 目录。

#### 蒸馏研究（析对手）

针对竞对分析中识别出的强样本，调用 `通用-蒸馏写作研究` 或 `通用-蒸馏作品蓝本`，提取可复用的叙事架构和套路指纹。

- **蒸馏写作研究**：从题材×平台级写作研究报告中提取可执行约束，产出写作研究模板。
- **蒸馏作品蓝本**：提炼一部成功作品的叙事架构 DNA 和套路指纹，产出作品蓝本模板（章首模式指纹、钩子轮换规律、回报间隔、节奏分布、套路配置）。例如：`蒸馏《诡秘之主》前100章作为蓝本`。

两条蒸馏产出统一注册到项目根 `Agents.md`。

**三层关系**：宏观市场分析回答"赛道值不值得进"——这是初始化前的方向决策；竞对分析回答"当前市场有什么空位、对手是谁"——这是初始化后的验证与细化；蒸馏研究回答"好作品有什么规律，如何借鉴"。三层逐级收窄，但竞对分析与蒸馏研究不影响初始化本身的方向性决策。

### 文风蒸馏（正文创作前的文笔准备，可选）

- **蒸馏作者文风**（`通用-蒸馏作者文风`）：提炼目标作家的文笔 DNA，产出作者风格模板（句长基线、段落节奏、感官偏好、对话标签偏好、比喻指纹、禁忌清单）。例如：`蒸馏猫腻的文风，分析《庆余年》和《间客》`。

与竞对与作品蒸馏段中的作品蓝本蒸馏不同——文风蒸馏不服务于商业化决策，只服务于具体写作执行。放在进入正文创作前做即可。

### 门禁 G1（宏观市场分析+初始化 -> 竞对研究/探索）

- 宏观市场分析已完成，研究报告已落盘到 `写作研究/` 目录
- 项目初始化蓝皮书的七维决策已全部完成
- 一句话卖点可复述
- 目标平台的市场定位清晰
- 开篇 3 章承诺可执行

### 门禁 G2（架构 -> 建模）

- 总纲 V1 可拆章、可连载
- 分卷起步节奏可落地
- 关键回报节点明确

### 门禁 G3（建模 -> 生产）

- 人设/设定/台账与总纲一致
- 无明显冲突或断链
- 能直接支撑章节施工

### 门禁 G4（生产 -> 发行）

- 章节质量达标（开头抓力/中段回报/章末钩子）
- 审阅报告闭环完成
- 母稿稳定可适配

分发执行：

- 通过 `小说分发/` 目录下各平台分发 Skill，实现自动化上传、草稿保存、分发日志与状态回写。
- 支持多平台并行分发、断点恢复、章节唯一键追踪等高级能力。

`小说分发/` 目录可用平台（当前已落盘）：

- 中文平台：番茄、七猫、起点、纵横、知乎、豆瓣、微信订阅号、小红书、新浪微博、百度百家号、B站
- 英文平台：WebNovel、My Fiction、GoodNovel

建议把分发理解为三层：

1. **编排层**：由 `多平台输出SOP` 决定“先母稿提纯、再平台改写、后分发上传”的顺序
2. **执行层**：调用 `小说分发/分发-平台名/SKILL.md` 完成登录、填充正文、保存草稿/发布
3. **回写层**：将章节状态、平台链接、失败原因、重试记录写回分发日志

目录边界提醒：`小说分发/` 是分发流程目录（不是题材目录）；可跨题材复用的稳定能力应回收至 `通用skills/`。

要求：

- 严格执行：母稿提纯 -> 平台适配 -> 平台输出 -> 平台分发。
- 平台版本要“真分化”，而非一稿换壳。

**建议澄清（详细说明）：**

- **章节创作**：
  - 推荐在同一个会话中通过一次命令连续撰写多章（如“请连续生成第6~10章”），这样便于保持情节连贯和上下文一致。

- **多平台输出（改写/适配）**：
  - 推荐“一个会话只处理一章的多平台版本”，即每次会话聚焦于某一章节，输出该章节的所有平台适配稿（如第7章的番茄、七猫、知乎等版本）。这样可以确保每个平台的改写风格、字数、内容要求都能针对本章做细致调整，便于比对和质量把控。
  - 如需批量处理多章多平台，可同时开启多个会话，每个会话负责不同章节的多平台输出（如会话A处理第7章，会话B处理第8章），实现并行提效。
  - 这样做的优点：每个会话上下文专注，便于追踪每章在各平台的差异和问题，减少混乱。

- **分发环节（上传到平台后台）**：
  - 由于大多数平台分发需要登录、验证码、人工确认等操作，推荐“一个会话专注于一个平台的多章上传”，即每次会话只负责一个平台，但可以批量上传多章（如一次上传第6~10章到番茄小说）。
  - 这样做的好处是：只需登录一次、验证一次，后续可连续上传多个章节，极大提升效率，减少因频繁切换平台或会话导致的重复验证和中断。
  - 若需分发到多个平台，可在不同会话分别处理（如会话A负责番茄，B负责七猫，C负责知乎），每个会话各自批量上传。

- **总结**：
  - 多平台输出时，建议“每会话一章多平台”，可多会话并行不同章节。
  - 分发上传时，建议“每会话一平台多章”，可多会话并行不同平台。
  - 这样既能保证内容适配的针对性，也能兼顾分发效率和人工操作便利。

## 5. 运营回流：把分发数据反哺创作（很多团队缺这一步）

多平台分发后，不是“完成”，而是进入下轮优化输入：

### 5.1 汇总读者反馈与完读/追更信号（按平台）

- 完读率、追更率、断更点分布（按章节与分卷）
- 评论高频关键词（人物、冲突、节奏、情绪回报）
- 转发/收藏触发点（哪些段落产生传播）

### 5.2 识别强反馈场景与弱反馈段落

- **强反馈**：高完读 + 高讨论，提炼“可复制抓手”
- **弱反馈**：低完读 + 低讨论，定位“掉速段/失温段”
- **意外爆点**：计划外高热内容，判断是否纳入卷级主线

### 5.3 回写到下一轮创作资产

- 回写到：下一卷大纲（节奏、冲突密度、卷末钩子）
- 回写到：章节控制卡（开头抓力、中段回报、章末驱动）
- 回写到：人物关系推进策略（热角色加压、冷角色回温）

这一步决定了你能否形成可持续迭代的连载引擎。

## 6. 常见误区与修正

1. **误把通用 Skill 当用户入口**
   - 修正：用户侧永远从题材目录 `prompt` 进入。

2. **总纲未稳就重度建模人物/设定/台账**
   - 修正：先轻量底盘，过 G2 再重度定稿。

3. **审阅只给聊天意见，不落盘**
   - 修正：审阅报告、补丁动作、复审结论都必须落库。

4. **多平台过早分发**
   - 修正：先把母稿做稳，再执行 `多平台输出SOP.prompt.md`。

5. **把编辑顺序做反**
   - 修正：先结构/发展层，再语言层，最后拷贝校对层。

6. **分卷节奏失控（中段卷失温）**
   - 修正：给每卷设“卷级回报点 + 卷末驱动点”，卷内每 5~8 章做一次节奏体检。

7. **卷间承接生硬（像换书而不是换卷）**
   - 修正：上一卷结尾预埋下一卷核心矛盾，下一卷前 2 章完成“回顾 + 升级 + 新承诺”。

## 7. 一份最短可执行清单（V2）

以女频爱情新书为例：

0. `宏观市场分析`（建议必选），完成方向定位（过宏观市场分析准入）。
1. `/小说项目初始化`，基于宏观市场分析产出完成项目初始化蓝皮书（必选，入门禁前置条件）。
2. `竞对分析`（可选）+ `蒸馏研究`（可选），完成定位验证与细化。若资源有限至少完成0和1即可进入后续步骤。
2. `蒸馏作者文风`（可选，正文创作前做）。
3. `深度研究`（可选） + `设计题材定位框架.prompt.md` + `设计大纲.prompt.md`，跑探索段并过 G1。
4. `设计大纲.prompt.md` + `审阅大纲.prompt.md` + `大纲审阅优化SOP.prompt.md`，跑架构段并过 G2。
5. `撰写人物传记.prompt.md` + `撰写技术手法程序证据设定.prompt.md` + 对应审阅 Prompt，跑建模段并过 G3。
6. `创建小说正文.prompt.md`（或 `撰写小说章节SOP.prompt.md`）+ 审阅/润色/去 AI 味，跑生产段并过 G4。
7. `评估签约概率.prompt.md` -> `组包投稿材料.prompt.md` -> `多平台输出SOP.prompt.md`，进入发行段并建立数据回流。

## 8. 外部方法论校准（本次联网复核要点）

本次联网检索到的共识（用于校准本流程）：

- **人物与情节需绑定**：角色设定应服务故事推进，而非孤立堆料。
- **编辑顺序应宏观先行**：先结构发展层，再句级层，再技术校对层。
- **外部读者反馈时机**：建议至少在较扎实二稿后再交 Beta/外部审阅。
- **连载宜分块嵌套**：场景 -> 章节 -> 弧线分层推进，并保留方向校准与迭代空间。

这与本仓库 V2 的“门禁 + 轻重分层 + 回流”方案一致。

---

## 9. 结语

这套 V2 最佳实践的目标，不只是“写完”，而是让你把灵感变成可持续生产线。

只要记住两句话：

1. **入口永远在题材 Prompt，不在通用 Skill。**
2. **总纲前轻建模，总纲后重定稿，分发后要回流。**

那么从第一章到多平台分发，流程会更稳、返工更少、迭代更快。

## 10. 开始创作前先做环境准备（小说工作目录）

> 这里的"工作目录"不是本项目根目录，而是你这本书自己的目录，例如：`她不再回头/`。

### 10.1 第一步：创建小说工作目录

示例目录：`D:\小说项目\她不再回头\`

### 10.2 第二步：在小说工作目录下创建 junction（Windows）

进入 `她不再回头/` 后，执行以下 5 条：

- `mklink /j .github 本项目中对应题材下的.github目录路径`
- `mklink /j 通用skills 本项目中的通用skills目录路径`
- `mklink /j 写作研究 本项目中对应题材下的写作研究目录路径`

例如当前题材是女频爱情，则 `.github` 与 `写作研究` 应指向 `女频爱情/` 下对应目录。

### 10.3 第三步：在 VS Code 中打开小说工作目录再调用

后续执行应使用：

- **斜杠命令**：如 `/深度研究`、`/设计题材定位框架`、`/竞对分析`、`/设计大纲`
- **上下文引用**：如 `#小说总大纲.md`、`#审阅意见/第06章审阅.md`

不是写 `女频爱情/.github/prompts/xxx.prompt.md` 这种路径命令。

## 11. 第一件事：创建项目配置文件

在 VS Code 中打开小说工作目录后，**第一件事**是创建或编辑工作目录根下的 `Agents.md`，注册主输出平台。`Agents.md` 同时也是蒸馏段产出的"写作研究模板""作者风格模板""作品蓝本模板"的注册文件。

```markdown
## 主输出平台
起点中文网
```

（若文件已有其他注册项如写作研究模板、作者风格模板等，将主输出平台注册项追加到同一文件末尾即可。）

该注册项被 `通用-创建小说正文`、`通用-章节创作闭环`、`通用-正文润色`、`通用-强化章末钩子` 等核心 Skill 自动发现，Skill 按命名约定加载对应的 `通用-输出{平台名}版` Skill，将平台特定规则与通用创作规则合并执行。若 `Agents.md` 不存在或未注册主输出平台，所有核心 Skill 回退平台无关的通用默认模式。

完成后，即可进入工作流的第一步——市场情报层（蒸馏 / 竞对分析）。

## 11. 调用时怎么写（/命令 + #引用 模板）

### 11.1 通用调用模板（可直接复制）

> /【命令名】
>
> 目标：一句话说清本轮要完成什么。
>
> 请读取以下上下文：
>
> - #文件A
> - #文件B
>
> 本轮约束：
>
> - 必须保留什么（例如成长线、关系线、关键设定）
> - 不能做什么（例如不新增事实、不改世界观硬规则）
>
> 输出要求：
>
> - 写回到哪个文件或目录
> - 需要几个版本（如主版 + 短版）
> - 聊天侧只回摘要，不贴全文

### 11.2 最小输入清单（防止“喂不饱”）

每次至少给这四类信息中的三类：

1. **对象**：处理哪本书、哪一卷、哪一章。
2. **依据**：#大纲、#正文、#人物、#设定、#审阅报告。
3. **目标**：本轮要提升什么（抓力、追更、签约概率、平台适配等）。
4. **约束**：哪些不能动（事实、时间线、角色定位、字数门槛）。

## 13. 快速迁移到其他题材（细化版）

把上述示例迁移到 `都市悬疑`、`赛博庞克`、`太空科幻` 时，建议按下列结构化项改动：

### 13.1 题材约束与禁行项

| 约束维度 | 修改点 |
| --- | --- |
| 冲突类型 | 将第 12 节示例中的冲突模板替换为该题材主冲突（如悬疑的证据链、科幻的规则冲突） |
| 禁行元素 | 在第 11 节模板“本轮约束”中加入平台审核红线与题材禁行项 |
| 风格边界 | 明确语言密度、写实度、设定解释比例，避免跨题材风格漂移 |

### 13.2 分卷与章节策略

- 按题材调节分卷长度与卷内爆点密度（爽文更高频、悬疑更证据驱动）
- 调整“卷末钩子”类型（悬疑偏谜面升级，科幻偏规则反转）

### 13.3 平台输出与分发策略

- 按题材热度重排平台优先级（先主战场，再扩散平台）
- 复用第 5 节运营回流指标，但替换为该题材的高频反馈词
- 为每个目标平台绑定一个固定分发 Skill（位于 `小说分发/分发-平台名/`），避免人工切后台导致状态丢失

### 13.4 审阅重点微调

- 复用第 6 节误区框架，补充题材特有风险。
- 都市悬疑重点排查：逻辑漏洞、证据断链、公平性不足。
- 赛博庞克/太空科幻重点排查：设定失稳、解释过载、规则代价缺失。

其余结构（目标、依据、约束、输出）保持不变。

## 1. 核心接口定义

### 1.1 事件总线 (Event Bus)

事件总线是微内核的中枢神经系统。所有插件间通信均通过事件总线进行，支持类型化事件、点对点和发布/订阅两种模式。

#### 类型定义

```python
class EventPriority(Enum):
    LOW = 0
    NORMAL = 50
    HIGH = 100
    CRITICAL = 200

class EventCategory(Enum):
    SYSTEM       = auto()   # 插件生命周期、配置变更
    PIPELINE     = auto()   # 章节生成流水线阶段
    QUALITY_GATE = auto()   # 门禁检查
    MEMORY       = auto()   # RAG 索引、事实账本、伏笔更新
    AGENT        = auto()   # Agent 间通信
    USER         = auto()   # 用户操作

@dataclass(frozen=True)
class EventEnvelope:
    event_id: str
    event_type: str              # 点号分隔, e.g. "pipeline.chapter.draft_complete"
    category: EventCategory
    priority: EventPriority = EventPriority.NORMAL
    source: str = ""             # 来源插件/Agent 名称
    timestamp: datetime
    payload: dict[str, Any]
    correlation_id: str | None   # 请求-响应配对
    ttl_seconds: int | None      # None = 永不过期
```

#### 事件总线接口

```python
class IEventBus(ABC):
    async def publish(self, envelope: EventEnvelope) -> None: ...
    async def request(self, envelope: EventEnvelope, timeout: float = 30.0) -> EventEnvelope: ...
    async def subscribe(self, event_type: str, handler: EventHandler, *,
                        priority: EventPriority = NORMAL,
                        filter_fn: Callable | None = None) -> str: ...
    async def unsubscribe(self, subscription_id: str) -> None: ...
    async def subscribe_many(self, event_types: list[str], handler: EventHandler, **kwargs) -> list[str]: ...
```

#### 内置事件类型

```python
class BuiltInEvents:
    # System

```

#### EventBus 实现要点

- 内部维护 `_subscribers: dict[str, list[SubscriberRecord]]`，按 event_type 索引
- 每个 event_type 对应一个 `asyncio.Queue`，由 per-type dispatcher 协程负责扇出
- `request()` 方法基于 `correlation_id` 创建一次性 `asyncio.Future`，响应方发布相同 correlation_id 的信封后自动匹配
- 支持按优先级排序投递

### 1.2 插件管理器 (Plugin Manager)

插件管理器拥有所有业务模块的完整生命周期。

#### 类型定义

```python
class PluginState(Enum):
    REGISTERED = "registered"
    LOADING    = "loading"
    ACTIVE     = "active"
    PAUSED     = "paused"
    ERROR      = "error"
    UNLOADING  = "unloading"
    UNLOADED   = "unloaded"

@dataclass

    name: str

    skills: list[dict[str, Any]]

@dataclass
class PluginEntry:

    instance: Any
    state: PluginState = PluginState.REGISTERED

    error_message: str | None = None
```

#### 插件接口（Protocol，非强制继承）

```python
class PluginHooks(Protocol):

    async def on_resume(self) -> None: ...
    async def on_chapter_before(self, ctx: dict) -> dict: ...
    async def on_chapter_after(self, chapter: dict) -> dict: ...
    async def on_gate_check(self, chapter: dict) -> "GateResult": ...
```

#### 插件管理器接口

```python
class IPluginManager(ABC):
    async def register(self, manifest: PluginManifest, instance: Any) -> None: ...
    async def load(self, name: str) -> None: ...
    async def unload(self, name: str) -> None: ...
    async def load_all(self) -> None: ...
    async def get(self, name: str) -> PluginEntry: ...
    async def list_active(self) -> list[PluginEntry]: ...
    async def resolve_dependencies(self, name: str) -> list[str]: ...
```

#### 依赖解析

- 使用 **Kahn 算法**（拓扑排序）解析插件依赖图
- 循环依赖 → `CircularDependencyError`
- 缺失依赖 → `PluginNotFoundError`
- 加载失败时反向调用 `on_unload()` 回滚已加载的插件

### 1.3 上下文管理器 (Context Manager)

提供命名空间化的共享状态存储，插件不持有可变内部状态，全部通过上下文管理器读写。

#### 接口

```python
class IContextManager(ABC):
    async def get(self, namespace: str, key: str, default: Any = None) -> Any: ...
    async def set(self, namespace: str, key: str, value: Any, ttl_seconds: int | None = None) -> None: ...
    async def delete(self, namespace: str, key: str) -> None: ...
    async def list_keys(self, namespace: str) -> list[str]: ...
    async def get_namespace(self, namespace: str) -> dict[str, Any]: ...
    async def set_many(self, namespace: str, items: dict[str, Any]) -> None: ...

    @asynccontextmanager
    async def transaction(self, namespace: str): ...
```

#### 规范命名空间

| 命名空间 | 用途 |
|---------|------|
| `project:<id>` | 项目级设定、角色、进度 |
| `session:<id>` | 会话级临时状态 |
| `pipeline:<id>` | 流水线阶段、门禁结果 |
| `agent:<name>` | Agent 工作草稿 |
| `global` | 跨项目配置 |

#### 实现要点

- 内存 dict-of-dicts 存储，每 namespace 一把 `asyncio.Lock`
- 后台任务每 30 秒逐出过期键
- `transaction()` 提供写锁 + 提交/回滚语义
- 后续可扩展 Redis/SQLite 后端（接口不变）

### 1.4 质量门禁 (Quality Gate)

门禁链是责任链模式，每道门禁检查章节并返回三种裁决之一。

#### 类型定义

```python
class GateVerdict(Enum):
    PASS   = "pass"    # 通过
    FAIL   = "fail"    # 不可恢复 → 升级给用户
    REVISE = "revise"  # 可恢复 → 送回修订

class Severity(Enum):
    INFO     = 0
    WARNING  = 1
    ERROR    = 2
    CRITICAL = 3

@dataclass
class GateIssue:
    severity: Severity
    code: str              # 机器可读, e.g. "consistency.timeline_gap"
    message: str           # 人类可读
    location: str | None   # 文本位置引用
    suggestion: str | None

@dataclass
class GateResult:
    gate_name: str
    verdict: GateVerdict
    issues: list[GateIssue]
    score: float = 1.0
    metadata: dict[str, Any]

class IQualityGate(ABC):
    name: str
    order: int
    async def evaluate(self, chapter: dict, context: dict) -> GateResult: ...

@dataclass
class GateChainConfig:
    gates: list[IQualityGate]
    max_revision_rounds: int = 3
    max_consecutive_revise: int = 2
    stop_on_first_fail: bool = True

class IGateChainExecutor(ABC):
    async def execute(self, chapter: dict, context: dict,
                      on_revise: Callable) -> GateChainResult: ...
```

#### 门禁链（Phase 2 实现）

| 顺序 | 名称 | 来源插件 | 检查内容 |
|:---:|------|---------|---------|
| 1 | consistency | 一致性审查器 | 时间线、人物行为、设定规则 |
| 2 | foreshadow | 伏笔管理器 | 活跃伏笔状态、无未授权丢弃 |
| 3 | style | 风格适配器 | 平台合规、移动端可读性 |
| 4 | anti_ai | AI 模式检测器 | AI 模式评分、困惑度、突发度 |
| 5 | final | 编排引擎 | 综合评分、字数、完整性 |

#### 五层记忆架构

| 层级 | 名称 | 访问模式 | 存储 |
|:---:|------|---------|------|
| L1 | 即时上下文 | 对话窗口内直接使用 | 内存 |
| L2 | 热记忆 | 每章 Prompt 自动注入 | 内存（最近 N 章摘要 + 活跃伏笔） |
| L3 | RAG 检索 | BM25 粗筛 → 语义精排 | ChromaDB |
| L4 | 知识图谱 | Cypher 结构化查询 | Neo4j |
| L5 | 冷存储 | 深度回溯时访问 | 文件系统（完整小说 + 历史版本） |

#### 检索策略

- **条件触发**: 日常过渡章跳过检索，关键情节/多人物交互触发
- **两阶段**: BM25 (粗筛 8 条) → 语义重排 (精排返回 Top-4)
- **Prompt Cache**: ~5K Token 规则块跨章节缓存，节省 30-50% Token

## 3. Agent 通信协议

### 3.1 Agent 发现机制

```
1. 插件加载 → 发布 system.plugin.loaded (含 AgentCapability)
2. 编排引擎订阅 system.plugin.loaded → 构建能力注册表
3. 编排引擎根据注册表路由流水线任务
```

### 3.3 章节生成流水线状态机

```
[IDLE] → [CONTEXT_ASSEMBLY] → [DRAFTING] → [STYLE_ADAPT]
```

## 5. 技术选型确认

| 技术 | 选择 | 理由 |
|------|------|------|
| **语言** | Python 3.12+ | 最成熟的 AI/ML 生态，native type 语法 |
| **Web 框架** | FastAPI | Async-native，Pydantic v2 集成，自动 OpenAPI |
| **数据模型** | Pydantic v2 (strict) | Rust 核心，strict 模式提前暴露问题 |
| **异步** | asyncio | 全链路 I/O 密集 (LLM, DB, FS) |
| **LLM SDK** | anthropic (官方) | Claude API 原生支持，prompt caching |
| **知识图谱** | Neo4j (neo4j-driver) | 原生图查询，Cypher 成熟 |
| **向量存储** | ChromaDB | 轻量嵌入式，Python-native，支持元数据过滤 |
| **关键词检索** | rank-bm25 + jieba | CJK 分词，第一轮粗筛 |
| **配置** | YAML + env vars | 三层合并，环境变量覆盖 |
| **日志** | structlog | 结构化日志，correlation_id 绑定 |
| **测试** | pytest + pytest-asyncio | 异步测试支持，fixtures |
| **HTTP 客户端** | httpx | 异步 HTTP，用于 LLM API + MCP SSE |
| **中文分词** | jieba | 中文分词，BM25 所必需 |
| **重试** | tenacity | LLM API 调用指数退避重试 |
| **代码质量** | ruff + mypy + pre-commit | 格式化 + 类型检查 |
| **容器化** | Docker + docker-compose | 一键部署 |

## 1. 项目概述

### 1.1 项目背景

当前网文市场（番茄小说日活突破 **3 亿**，起点、晋江等平台持续增长）对内容产出的速度和质量要求日益提高。然而：

- **新人作者**面临"不知道怎么开始"的困境——从选题、大纲到正文，缺乏系统指导；
- **成熟作者**面临日更压力（番茄全勤要求日更 ≥ 4000–6000 字），持续产出高质量内容存在瓶颈；
- **AI 直接生成**的文本存在"AI 味"重、平台查重/检测风险高、前后设定矛盾等问题。

本项目的目标是构建一个 **AI 原生小说创作智能体系统**，以 **多 Agent 协作 + RAG 知识库 + MCP 工具链** 为技术底座，提供从灵感到成书的完整创作辅助能力，同时内置反 AI 检测引擎确保产出文本的真实性与安全性。

### 1.2 项目定位

| 维度 | 定位 |
|------|------|
| **目标用户** | 网文新人作者、成熟作者（辅助提效）、自媒体短篇创作者 |
| **覆盖平台** | 番茄小说、起点中文网、晋江文学城、七猫、豆瓣阅读 |
| **核心价值** | 降低创作门槛 + 提升产出效率 + 保障文本安全 |
| **技术理念** | 微内核 + 插件架构，AI 可自我扩展（Meta-Generation） |

## 3. 系统总体架构

### 3.1 架构设计原则

1. **微内核 + 插件架构**：核心引擎极简稳定，所有业务能力以插件/Skill 形式挂载，支持热插拔。
2. **Agent 专业化分工**：不同职责由独立 Agent 承担，通过事件总线协作，避免单 Agent 承担过多职责导致上下文污染。
3. **分层 RAG 记忆**：BM25 粗筛 → 语义精排 → 知识图谱关联，条件触发的检索策略（日常过渡场景跳过检索）。
4. **质量门禁驱动**：每章产出后必经多道质量门禁（一致性 → 风格 → 反AI → 门禁检查），`passed: true` 才解锁下一章。
5. **模型分层路由**：不同复杂度任务使用不同层级模型，优化成本与质量。

## 4. 模块一：小说生成模块

小说生成模块是本系统的核心业务模块，覆盖从灵感孵化到正文产出的完整创作流水线。

### 4.1 子模块划分

```
小说生成模块
├── 4.1 灵感孵化器 (Idea Incubator)
├── 4.2 设定构建器 (World Builder)
├── 4.3 大纲规划器 (Outline Planner)
├── 4.4 正文撰写引擎 (Chapter Writer)
├── 4.5 一致性审查引擎 (Consistency Checker)
├── 4.6 伏笔管理器 (Foreshadow Tracker)
└── 4.7 风格/平台适配器 (Style Adapter)
```

### 4.2 子模块详细需求

#### 4.2.1 灵感孵化器

| 需求项 | 说明 |
|--------|------|
| **输入** | 一句话灵感、关键词、梗概、或"随机生成"指令 |
| **处理流程** | ① 解析输入 → ② RAG 检索相关题材的爆款模式 → ③ 生成 3-5 个扩展方向 → ④ 用户选择/合并 |
| **输出** | 核心梗概（Logline）+ 类型标签 + 目标平台建议 |
| **参考资料** | 番茄小说作家课堂写作技巧、各平台爆款分析 |

#### 4.2.2 设定构建器

| 需求项 | 说明 |
|--------|------|
| **世界观设计** | 时间线、地理、势力分布、核心规则（如修炼体系）、历史事件 |
| **人物小传** | 基础档案 + 性格标签 + 外貌 + 背景故事 + 核心动机 + 人物弧光规划 |
| **关系网络** | 人物关系图谱（盟友/敌对/师徒/情感/从属等），自动写入知识图谱 |
| **输出格式** | SETTINGS.md + CHARACTERS.md 结构化文件 + Neo4j 节点/边 |

#### 4.2.3 大纲规划器

| 需求项 | 说明 |
|--------|------|
| **分卷规划** | 整书分卷，每卷有明确的起承转合和核心冲突 |
| **章节节点** | 每章标题 + 一句话梗概 + 关键事件 + 人物关系转折点 |
| **节奏控制** | 根据平台特性自动调整高潮密度（番茄：每3-5章一个小高潮） |
| **名场面标注** | ⭐ 标注商业看点/"名场面"节点 |
| **输出格式** | PROGRESS.md 结构化大纲 + 进度配额（quota: min/max progress） |

#### 4.2.4 正文撰写引擎

这是最核心的子模块，采用多 Agent 接力 + 质量门禁的模式。

| 需求项 | 说明 |
|--------|------|
| **写作 Agent** | 专职正文生成，接收大纲节点 + RAG 上下文 + 风格指令 |
| **上下文注入策略** | ① 当前大纲节点 ② 前 4 章摘要（RAG 精排） ③ 相关人物/设定片段 ④ 活跃伏笔列表 ⑤ 事实账本 |
| **生成模式** | 支持单章生成、批量连续生成（带人工审核断点） |
| **字数控制** | 可配置目标章节字数范围（默认 2000-4000 字/章） |
| **移动端优化** | 段落 ≤ 5 行 / 对话单独成行 / 少心理环境描写 / 快节奏 |
| **平台风格** | 根据目标平台自动注入不同的叙事策略（见 4.2.7） |

**写作 Agent 的 Prompt 结构**（参考现有 `novel-app-system-prompt.md`）：

```
System Prompt = 角色定义 + 核心原则 + 平台知识 + 上下文快照
  上下文快照 = {
    当前大纲节点,
    RAG 检索结果 (Top-K 相关片段),
    活跃伏笔清单,
    事实账本 (关键数值/状态),
    风格校准参数
  }
```

**模型路由策略**（按任务分层）：

| 任务类型 | 推荐模型层级 | 理由 |
|---------|:-----------:|------|
| 正文撰写、润色 | Premium（如 Opus） | 创意质量要求最高 |
| 风格指南、大纲规划 | Standard（如 Sonnet） | 结构化分析 |
| 一致性检查、事实提取 | Standard | 逻辑校验 |
| RAG 索引、元数据提取 | Budget（如 Haiku） | 纯抽取任务 |

#### 4.2.5 一致性审查引擎

| 需求项 | 说明 |
|--------|------|
| **检查维度** | 人物行为一致性、时间线连续性、设定规则遵守、对话语气匹配 |
| **事实账本** | 自动提取每章的硬事实（金额、数量、地名、时间节点），下一章自动校验 |
| **交叉审查** | 使用与写作 Agent **不同模型**的双 Agent 交叉验证，防止自我偏见 |
| **修改上限** | 每章最多 3 轮修订；连续 3 次"条件通过" → 触发人工介入 |
| **输出格式** | 审查报告（问题清单 + 严重级别 + 修改建议） |

#### 4.2.6 伏笔管理器

| 需求项 | 说明 |
|--------|------|
| **生命周期状态** | `planted（已埋） → building（发展中） → paid（已回收） / dropped（已废弃）` |
| **自动注入** | 活跃伏笔自动注入下一章 Prompt，确保模型"记得"未回收的伏笔 |
| **回收检测** | 每章产出后检测是否有伏笔被自然地回收/推进 |
| **废弃审批** | `dropped` 状态需人工确认，防止模型擅自丢弃情节线 |

#### 4.2.7 风格/平台适配器

| 平台 | 风格特征 | 技术参数 |
|------|---------|---------|
| **番茄小说** | 开篇冲突密集，语言极简，每3-5章小高潮，强调爽感 | 段落短、对话多、少描写、高密度钩子 |
| **起点中文网** | 快节奏、强冲突，升级感明确，金手指清晰 | 章节末尾强钩子、修炼/成长节点突出 |
| **晋江文学城** | 强人设、重感情线，节奏可缓，细腻心理描写 | 允许更多内心戏、CP 互动细节 |
| **七猫小说** | 类似番茄，但更偏女频甜宠、霸总 | 情感张力优先 |
| **豆瓣阅读** | 文学性强，人物弧光与社会议题，文笔精致 | 允许更深度的描写与议论 |

风格参数以 **可配置的 JSON Profile** 形式存储，支持用户自定义和社区分享。

## 5. 模块二：反AI检测模块

### 5.1 模块定位

反AI检测模块的目标是确保生成的小说文本：
1. **通过主流 AI 检测工具**（如 GPTZero、Originality.ai、各平台内部检测）
2. **读起来像人写的**——消除"AI 味"，而非简单的检测规避
3. **保持文学质量**——改写不降低文笔水准

### 5.2 子模块划分

```
反AI检测模块
├── 5.1 AI 模式检测器 (Pattern Detector)
├── 5.2 文本指纹分析器 (Text Fingerprint Analyzer)
├── 5.3 风格人性化引擎 (Humanization Engine)
├── 5.4 对抗改写器 (Adversarial Rewriter)
└── 5.5 检测结果报告 (Detection Report)
```

### 5.3 子模块详细需求

#### 5.3.1 AI 模式检测器

基于行业研究（NovelForge Tic 防御系统、Antislop 框架），建立 **AI 写作模式特征库**：

| 类别 | 检测模式 | 检测方法 | 严重度 |
|------|---------|---------|:-----:|
| **高频 AI 词** | "不禁"、"仿佛"、"映入眼帘"、"与此同时"、"诚然" | 词频统计 + 阈值告警 | 高 |
| **弱化副词过量** | "微微"、"淡淡"、"缓缓"、"轻轻" | 每千字计数 > 3 触发 | 中 |
| **意义膨胀** | "意义深远"、"前所未有"、"空前绝后" | 正则 + 语义匹配 | 中 |
| **泛化结尾** | "未来可期"、"充满希望"、"新的篇章" | 章节末段专项检测 | 高 |
| **议论文结构** | "不难看出"、"由此可见"、"综上所述" | 正则模式匹配 | 中 |
| **正式语域** | 过于书面化的连接词、缺少口语节奏 | 句式复杂度分析 | 中 |
| **排比句过量** | "勇气、智慧和决断力" 类型的三联排比 | 句法结构分析 | 低 |
| **均匀句长** | AI 输出的句长标准差偏低 (SD < 4) | 统计学检测 | 高 |
| **低困惑度文本** | 文本对生成模型而言"过于可预测" | 困惑度 (Perplexity) 计算 | 高 |
| **缺乏感知细节** | 缺少五感描写（视/听/嗅/味/触） | 语义角色标注 | 中 |

#### 5.3.2 文本指纹分析器

| 需求项 | 说明 |
|--------|------|
| **困惑度分析** | 计算文本在多模型下的困惑度分数，识别"过于平滑"的 AI 特征 |
| **突发度分析** | 句长分布的标准差和变异系数，人类写作通常 SD > 4 |
| **词汇多样性** | Type-Token Ratio (TTR)、Hapax Legomena 比例 |
| **N-gram 重复度** | 检测 AI 常见的短语复用模式 |
| **外部检测 API 集成** | 对接 GPTZero、Originality.ai 等外部检测服务（MCP Server 形式） |

#### 5.3.3 风格人性化引擎

| 技术 | 说明 | 参考来源 |
|------|------|---------|
| **感知细节注入** | 在适当位置添加五感描写，打破 AI 的抽象概括倾向 | 创意写作教学 |
| **句式变异** | 刻意变化句长，插入短句/断句，制造节奏起伏 | 突发度校准 |
| **口语化处理** | 根据角色身份替换书面词汇为口语表达 | 对话自然度 |
| **主观性注入** | 在旁白中适度加入角色主观感受和即时反应 | 人类写作特征 |
| **不完美引入** | 允许适当的重复、迟疑、修正——人类写作的自然痕迹 | Antislop 框架 |
| **章节末钩子改写** | 将泛化结尾替换为具体悬念/冲突 | 网文写作技巧 |

#### 5.3.4 对抗改写器

| 需求项 | 说明 |
|--------|------|
| **两遍编辑协议** | 第一遍清除 AI 模式；第二遍 AI 自审"哪些部分还有 AI 味"并修正 |
| **改写强度分级** | 轻度（仅去 AI 词）、中度（句式变化）、重度（段落重写） |
| **质量保持** | 改写后语义相似度 > 0.94，不损失情节和人物塑造 |
| **用户可控** | 用户可选择改写强度、保留特定段落不修改 |

### 7.2 RAG 引擎设计

#### 7.2.1 五层记忆架构

```
Layer 1: 即时上下文 (对话窗口内)
    └── 当前章节的完整上下文，够模型直接处理

Layer 2: 热记忆 (最近 N 章摘要 + 活跃伏笔)
    └── 自动注入每章 Prompt，确保短期连贯

Layer 3: RAG 检索 (BM25 粗筛 → 语义精排)
    └── 条件触发（复杂情节时检索，日常过渡跳过）

Layer 4: 知识图谱 (Neo4j)
    └── 结构化关系查询，处理"XX 的师父是谁"类问题

Layer 5: 冷存储 (完整小说文件 + 历史版本)
    └── 仅在需要深度回溯时访问
```

#### 7.2.2 RAG 检索策略

| 策略 | 说明 |
|------|------|
| **两阶段检索** | BM25 (粗筛候选池，默认 8 条) → 语义重排 (精排返回 Top-K，默认 4 条) |
| **条件触发** | 轻量场景（日常/过渡章）跳过检索；复杂场景（关键情节、多人物交互）触发检索 |
| **混合检索** | 向量相似度 + 关键词匹配 + 知识图谱结构化查询 |
| **缓存策略** | Prompt Cache 缓存 ~5K Token 的规则块，跨章节约 30-50% Token |

#### 7.2.3 知识图谱设计

```
节点类型:
  Character  (人物)    — 姓名、别名、年龄、修为、性格标签、当前状态
  Location   (地点)    — 名称、类型、所属势力、首次出现章节
  Faction    (势力)    — 名称、类型、领袖、成员、敌对/同盟
  Item       (物品)    — 名称、类型、持有者、能力/效果
  Event      (事件)    — 名称、时间点、涉及人物、影响
  Foreshadow (伏笔)    — 内容、状态(planted/building/paid/dropped)、涉及人物
  WorldRule  (世界观)  — 规则类型、描述、例外情况
  PowerSystem(力量体系)— 等级、能力、突破条件

关系类型:
  ally, enemy, master_disciple, subordinate, emotional,
  belongs_to, located_at, triggers, foreshadows, possesses,
  knows_about, transforms_into, conflicts_with
```

每次章节完成后自动提取实体和关系，写回知识图谱。大纲变更时，受影响节点级联重算。

### 7.3 本地化 RAG 方案（降级策略）

考虑到用户可能无法始终使用云端 API，提供全本地运行的降级方案：

## 11. 风险评估与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|:-----:|:---:|---------|
| **LLM API 成本过高** | 中 | 高 | ① 模型分层路由（Haiku 处理轻任务）② Prompt Cache 节省 30-50% ③ 本地 Ollama 降级 |
| **生成内容同质化** | 高 | 中 | ① 风格多样性参数 ② 不同模型混用 ③ 反AI模块深度改写 |
| **长篇设定漂移** | 高 | 高 | ① 五层记忆架构 ② 每章质量门禁 ③ 知识图谱关联校验 |
| **平台检测封禁** | 中 | 高 | ① 反AI检测模块前置 ② 文本指纹分析 ③ 对抗改写确保通过 |
| **版权与原创性争议** | 中 | 中 | ① RAG 检索结果仅作参考不直接复制 ② 原创度检测 ③ 用户最终审核 |
| **用户过度依赖** | 低 | 低 | ① 保持"辅助"定位 ② 提供写作技巧学习 ③ 人工审核断点 |
| **MCP 安全性** | 低 | 高 | ① 仅加载受信任的 MCP Server ② 沙箱执行环境 ③ 用户授权确认 |
| **番茄等平台规则变更** | 中 | 中 | ① 知识库定期更新机制 ② 规则变更告警 ③ 插件化设计便于快速适配 |
